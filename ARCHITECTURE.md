# Архитектура Zapret Desktop и связь с исходным проектом

## Исходные компоненты

Каталог `zapret/`, включённый в поставку, содержит дистрибутив Flowseal: `service.bat`
версии 1.10.4, 22 стратегии `general*.bat`, каталоги `bin/` и `lists/`, а также
`utils/test zapret.ps1`. В локальной копии отсутствуют `README.md` и `.service/`;
уведомление `LICENSE.txt` включено в комплект. Исходный проект доступен в
<https://github.com/Flowseal/zapret-discord-youtube>. Исполняемый файл и драйвер
остаются компонентами исходного проекта. Desktop не должен переопределять их
логику обхода DPI.

Адаптированный скрипт автоподбора хранится в
`src/Zapret.Infrastructure/Scripts/TestStrategies.ps1` и встраивается в сборку Desktop.
При запуске он получает путь к актуальному дистрибутиву отдельным параметром;
обновление `zapret/utils/test zapret.ps1` не меняет автоподбор Desktop.

| Существующая возможность | Источник | Реализация в Desktop |
| --- | --- | --- |
| Ручной запуск стратегии | `general*.bat` | Найти вызов `winws.exe`, разобрать его на аргументы и запустить `bin/winws.exe` через `ArgumentList`, указав `bin` как рабочий каталог. Неизвестные конструкции BAT-файла отклонять. |
| Выбор стратегии и установка службы | `service.bat :service_install` | Использовать разобранную стратегию при установке службы `zapret`; сохранять имя выбранного исходного файла в существующем значении реестра. |
| Состояние процесса и службы | `:status_zapret`, `:service_status` | При каждом обновлении запрашивать состояние у ОС. Различать процесс, запущенный Desktop, сторонний `winws` и службу `zapret`. Обычная остановка не должна завершать сторонний процесс. |
| Игровой фильтр | `:game_switch_status`, `:game_switch` | Читать и записывать `utils/game_filter.enabled`. Фактические режимы: `disabled`, `all`, `tcp`, `udp`. В режиме `disabled` подставляется порт `12`; диапазон по умолчанию при включённом фильтре — `1024-65535`. Пользовательские диапазоны TCP/UDP нужно сохранять. Требуется перезапуск стратегии. |
| Фильтр IPSet | `:ipset_switch_status`, `:ipset_switch` | Читать и записывать `lists/ipset-all.txt` и `.backup`. Фактические состояния: `loaded` (настоящий список), `none` (маркер `203.0.113.113/32`), `any` (пустой файл). Без резервной копии восстановить режим `loaded` нельзя. |
| Пользовательские списки | `:load_user_lists`, `lists/*-user.txt` | Создавать отсутствующие пользовательские файлы в формате исходного проекта и изменять их атомарной заменой. Большие списки исходного проекта обрабатывать потоково или постранично. |
| Тесты и автоматический подбор | `service.bat :run_tests`, `utils/test zapret.ps1`, `utils/targets.txt` | Встроенный адаптированный PowerShell-сценарий с типизированным протоколом запуска/результатов и отменой. В DesktopMode запуск и остановка проходят через C# process ownership; snapshot/повторный запуск чужих процессов отключён. Рекомендация сохраняется отдельно от выбора пользователя. |
| Диагностика | `:service_diagnostics` | Проверки только для чтения: файлы, BFE, WinDivert, прокси, путь, конфликты, DNS, hosts и службы. Исправления из BAT-файла, способные удалить или изменить данные, должны быть отдельными явными действиями в интерфейсе. |
| Проверка обновлений | `:service_check_updates`, `.service/version.txt` | Раздельно проверять выпуски Desktop и исходного проекта. Если `.service/version.txt` отсутствует, брать локальную версию из `LOCAL_VERSION` в `service.bat`. |
| Замена активных фейковых пакетов | `:replace_active_fakes`, `bin/ACTIVE_*.bin` | Предлагать только `.bin`-файлы из поставки и заменять активный файл атомарно; показывать сравнение хешей. |
| Обновление IPSet и hosts | `:ipset_update`, `:hosts_update` | Скачивать данные только по фиксированным URL исходного проекта. Проверять IPSet и заменять его атомарно. Обновление hosts допускается только после просмотра пользователем, поскольку оно меняет системный файл. |
| Параметры запуска и обновлений | `utils/check_updates.enabled`, автоматический запуск службы | Запуском Desktop управляют настройки Desktop в JSON. Автоматический запуск службы `zapret` — отдельный параметр службы Windows. |

`Zapret.Core` определяет модели и границы компонентов. `Zapret.Infrastructure`
содержит адаптеры для файлов, процессов, служб, реестра, привилегий, HTTP и
сценариев. `Zapret.Desktop` содержит представления и модели представлений
Avalonia. Отдельная абстракция дистрибутива находит локальный корневой каталог
исходного проекта и проверяет его файлы; интерфейс не должен исходить из
фиксированного количества стратегий.

## Важные ограничения совместимости и безопасности

- В BAT-файлах стратегий используются `%BIN%`, `%LISTS%`, `%GameFilterTCP%`,
  `%GameFilterUDP%`, продолжение строки через `^` и иногда экранированное `^!`.
  Парсер должен сохранять границы аргументов и отклонять неизвестные подстановки
  переменных или команды.
- `service.bat` устанавливает службу `zapret` командой `sc create` с параметром
  `start= auto`, затем записывает
  `HKLM\System\CurrentControlSet\Services\zapret\zapret-discord-youtube`.
  При удалении он также завершает все процессы `winws.exe` и удаляет службы
  WinDivert. Desktop должен ограничивать область таких действий и сообщать
  пользователю об этом отличии.
- Оригинальный сценарий PowerShell изменяет `ipset-all.txt`, запускает BAT-файлы,
  завершает все экземпляры `winws` и ждёт ввода. Desktop использует встроенный
  адаптированный сценарий: команды запуска/остановки исполняются C#-адаптером,
  а stdin используется для ответа протокола. Перед тестом запрещены работающая
  служба и обнаруженный внешний winws. После отмены/прерванного запуска
  восстанавливается IPSet. Оставшиеся границы доверия TEMP/PATH/targets описаны
- Диагностика `:service_diagnostics` исходного проекта после подтверждений может
  удалить конфликтующие службы и кеш Discord. Диагностика Desktop должна
  сообщать о найденных проблемах, не выполняя этих действий.
- Не включать бинарные компоненты в релиз, пока не будут проверены и добавлены
  уведомления о лицензиях MIT для Flowseal/bol-van и выполнены требования
  LGPLv3/GPLv2 для WinDivert.

## Возможности версии 0.2.0

- `DataProtection` управляет ZIP копиями и оригиналами payload; импорт валидирует allowlist, размер, SHA-256 и игровые фильтры. Перед записью сохраняются текущие данные; неудачная запись откатывается. `SettingsHealth` сохраняет повреждённый JSON и показывает предупреждение вместо молчаливого сброса.
- `ManagedUpdates` разделяет загрузку/проверку и применение. Архивы сверяются с GitHub digest и после копирования; пользовательские списки сохраняются. Directory swap имеет резервный каталог и rollback при обработанном исключении текущего сеанса; durable journal и автоматическое восстановление после crash/restart отсутствуют. Помощник Desktop и manifest создаются атомарно в Program Files с правами только Administrators/SYSTEM. Новый каталог приложения допускает Users ReadExecute для запуска перед elevation, без права записи. hosts имеет предпросмотр, точные маркеры и защиту от изменения файла между просмотром и применением.
- `HealthAndHistory` хранит результаты HTTP/TLS отдельно от состояния процесса; история содержит неизменяемый снимок результатов и подробный отчёт. Progress сохраняется синхронно, чтобы очереди UI не теряли последний результат.
- Desktop предоставляет явное применение выбора/фильтров, импорт/экспорт/восстановление, обновления и просмотр отчётов. Параметры активной службы подтверждаются фактической командой из CIM в диагностике; конфигурация реестра не считается доказательством параметров работающего процесса.
- Локальный скрипт `scripts/Build-Release.ps1` выполняет Core/Desktop/headless GUI tests, собирает Release, проверяет состав ZIP и выводит SHA-256 архива. Архив публикуется в GitHub Releases вручную.

## Согласованные улучшения от 24.10.2026

- `SettingsDraft` хранит редактируемые значения отдельно от сохранённых моделей и пересоздаваемых контролов. Инициализация и явные import/restore загружают draft; update/rollback сохраняют несохранённый ввод. Применение фильтров валидирует весь блок и возвращает прежние bytes при обработанной ошибке записи; это не crash-атомарная транзакция нескольких файлов.
- `PreparationViewModel` выполняет одну отменяемую подготовку вне engine gate. Подготовка не удерживает Start/Stop/выбор стратегии; применение файлов сериализовано и запрещено во время подготовки. Выход отменяет подготовку и ждёт cleanup, публикация отменённого плана подавляется.
- Рекомендация строится по завершённым `__ZD_RESULT__` только после успешного текущего START; failed/late результаты отбрасываются. При отмене последний завершённый результат сохраняется. HTTP/Ping ranking сохраняет первый равный результат.
- `ZapretServiceStatus` переносит состояние и PID SCM. Pending/unknown не разрешают ручной запуск; PID независимого winws не подставляется вместо PID службы.
- `InterruptedTestRecoveryException` выделяет отсутствие тестовой копии. Запуск блокируется; import/restore выбранной пользовательской копии разрешены после остановки движка/службы. UI требует подтверждение, проверенный IPSet снимает marker. Безопасный выход останавливает только owned processes и сохраняет marker до восстановления.
- `CheckConnectionAfterStart` по умолчанию true; старые settings/backup совместимы. Проверка версий не открывает браузер. Ошибки сохраняются до скрытия пользователем, повтор той же ошибки вновь виден.



## Проверка реального окружения



Автоматические тесты используют временные файлы, подмены Windows/HTTP/DNS и headless Avalonia. PowerShell helpers запускаются только на временных фикстурах. Они не устанавливают настоящий драйвер, не меняют системный hosts и не подтверждают эффективность обхода DPI. Реальные запуск/служба/автозагрузка и видео/голос проверяются отдельно в изолированном Windows 10/11 x64 окружении с повышенными правами.
