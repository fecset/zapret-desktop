# Архитектура Zapret Desktop

Zapret Desktop управляет Windows-дистрибутивом [Flowseal](https://github.com/Flowseal/zapret-discord-youtube). Движок `winws.exe`, драйвер WinDivert, стратегии и payload находятся в `zapret/`. Desktop предоставляет интерфейс и управляет этими компонентами; алгоритмы обхода остаются в движке.

## Структура решения

| Проект | Назначение | Зависимости |
| --- | --- | --- |
| `Zapret.Core` | Модели состояний и интерфейсы служб | Стандартная библиотека .NET |
| `Zapret.Infrastructure` | Файлы, процессы, SCM, Планировщик заданий, HTTP и PowerShell | `Zapret.Core` |
| `Zapret.Desktop` | Интерфейс Avalonia и координация пользовательских действий | `Zapret.Core`, `Zapret.Infrastructure` |

[App.cs](src/Zapret.Desktop/App.cs) регистрирует зависимости и создаёт окно, трей и общий `MainViewModel`. Его реализация разделена на partial-файлы: `FeatureViewModel.cs`, `FilterViewModel.cs`, `PreparationViewModel.cs` и `RecoveryViewModel.cs`. `SettingsDraft` хранит несохранённые значения настроек и фильтров.

Корень дистрибутива выбирает `App.FindDistribution()`. Класс `ZapretDistribution` получает готовый путь, предоставляет расположение файлов и проверяет комплектность. Версия движка читается из `.service/version.txt`, а при его отсутствии — из `LOCAL_VERSION` в `service.bat`. Стратегии находятся по файлам `general*.bat`.

## Запуск и управление движком

[Program.cs](src/Zapret.Desktop/Program.cs) проверяет права администратора до создания интерфейса. Именованные mutex и событие ограничивают запуск одним экземпляром и позволяют повторному запуску открыть существующее окно.

`ZapretProcessManager` различает процесс, запущенный Desktop, внешний `winws.exe` и службу Windows. Для остановки используется сохранённый объект процесса, запущенного Desktop. Выход из приложения останавливает этот процесс; независимая служба управляется отдельно.

`ScServiceManager` получает состояние службы и PID через SCM. Переходное или неопределённое состояние блокирует конфликтующий ручной запуск. Служба хранит готовую команду с аргументами: Desktop обновляет её при установке, запуске и перезапуске службы. Запуск через сам SCM использует последнюю записанную команду, поэтому для применения новых фильтров к службе нужен запуск или перезапуск из Desktop.

Автозапуск интерфейса регистрирует `WindowsStartupService` в Планировщике заданий для текущего пользователя с повышенными правами. При загрузке настроек Desktop сверяет регистрацию с ОС. Запуск выбранной стратегии при открытии приложения хранится в JSON; автоматический запуск службы настраивается отдельно в SCM.

## Стратегии и автоподбор

`BatStrategyProvider` и `BatStrategyParser` читают BAT-файлы и извлекают команду `winws.exe`. Парсер поддерживает подстановки путей и игровых портов, отклоняет неизвестные подстановки и операторы в аргументах. Обычный запуск передаёт аргументы через `ProcessStartInfo.ArgumentList`, без исполнения BAT в командной оболочке.

Автоподбор использует [встроенный сценарий PowerShell](src/Zapret.Infrastructure/Scripts/TestStrategies.ps1), адаптированный для Desktop. Файл `zapret/utils/test zapret.ps1` сохраняется как самостоятельный сценарий Flowseal; обновление дистрибутива не подменяет встроенную версию. Стратегии и цели проверки берутся из текущего каталога `zapret`.

`PowerShellStrategyTester` обменивается со сценарием командами запуска, остановки и результатами через стандартные потоки. Движок запускает C#-адаптер, который отслеживает принадлежность процесса. Для теста должны быть остановлены все экземпляры `winws.exe`, а служба `zapret` должна отсутствовать, даже если она остановлена.

Во время автоподбора редактирование списков и диагностика недоступны. После отмены или прерванного теста восстанавливается исходный IPSet. Если тестовая копия утрачена, запуск блокируется до подтверждённого восстановления из пользовательской копии или ZIP. Отмена теста сохраняет последний завершённый результат.

## Данные и изменения

- В `zapret/lists` находятся домены и IP-адреса. `ListService` выполняет потоковый поиск с лимитом результатов; редактирование читает файл целиком и записывает его атомарной заменой.
- `FilterService` хранит Game Filter в `utils/game_filter.enabled`. Режим IPSet определяется содержимым `lists/ipset-all.txt`: список адресов, маркер отключения или пустой файл. Копия `.backup` нужна для возврата загруженного списка.
- В `%LOCALAPPDATA%\ZapretDesktop` находятся настройки, история тестов, резервные копии и оригиналы заменённых payload. `JsonSettingsStore` пытается сохранить повреждённый JSON отдельно и возвращает настройки по умолчанию; интерфейс показывает предупреждение, в том числе при неудачной записи копии.
- `UserDataBackupService` проверяет имена файлов, размеры и SHA-256 в ZIP. Восстановление сохраняет отсутствующие в архиве настройки и файлы; пустые персональные списки не очищают существующие записи. Перед записью состояние удерживается в памяти для отката обработанной ошибки. Импорт и восстановление не создают новые архивы.
- В ZIP входят стандартные списки дистрибутива, `list-custom.txt`, `ipset-custom.txt`, фильтры, настройки и активные payload. Произвольно названные дополнительные списки вне этого набора нужно переносить отдельно.
- Автоматические копии создаются перед важными изменениями, одинаковые состояния не дублируются. Лимит десять относится к новым автоматическим архивам, учтённым индексом; ручные и прежние копии не удаляются.

Операции изменения состояния сериализуются в `MainViewModel`. Проверка соединения и отменяемая подготовка обновлений, IPSet и hosts выполняются отдельно, чтобы не задерживать остановку движка. Применение подготовленных файлов требует остановленного движка и службы.

`ManagedUpdateService` разделяет загрузку, проверку и установку. Проверяются адрес источника, содержимое архива и контрольная сумма. При обновлении дистрибутива сохраняются пользовательские списки и payload; прежний каталог используется для отката. Обновление Desktop выполняет отдельный помощник после выхода из приложения.

Hosts изменяется только после предпросмотра и подтверждения. Перед записью проверяется, что файл не изменился с момента предпросмотра; пользовательские строки сохраняются. Совпадающее содержимое повторно не записывается. `DiagnosticService` выполняет проверки без изменения системных файлов.

## Проверки и ограничения

`Zapret.Core.Tests` проверяет инфраструктуру и обработку данных; `Zapret.Desktop.Tests` — модели представлений, жизненный цикл и интерфейс через headless Avalonia. Тесты используют временные файлы и подмены Windows, HTTP и DNS.

Откат при обработанном исключении не обеспечивает восстановление после отключения питания: общего журнала транзакций для обновлений и изменений нескольких файлов нет. Настоящие драйвер, служба, UAC и работа обхода DPI проверяются отдельно в Windows. Контрольный HTTP-ответ не подтверждает воспроизведение видео или голосовую связь.
